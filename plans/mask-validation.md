# 构图蒙版有效性验证方案

> 状态：可复用的产品验证方案，待执行项与已完成实验分开记录。核对日期：2026-09-28。
>
> 2026-09-05 的首轮 26 张成片观察已完成，见 [实拍记录](./field-validation-2026-09-05.md)。本文件不再沿用 Expo development build、Skia 或跨平台相机桥接方案。
> 当前 iOS 实现见 [当前状态](./current-status.md)，后续验证与改进状态见 [后续工作](./next-steps.md)。

## 1. 验证假设与现有证据

核心假设是：用户在真实取景画面上看到构图蒙版后，能否更容易完成构图，并拍出更符合预期的照片。

首轮成片观察为静态蒙版的构图表达提供方向性支持，也发现用户可能选错场景。它没有无蒙版对照、构图耗时或拍摄者反馈，因此以下问题仍未得到结论：

- 蒙版是否比无引导更快、更易用。
- 新用户能否独立选择合适模板。
- 哪些几何限制有帮助，哪些会造成干扰。
- 当前 SwiftUI 相机中预览、蒙版与输出是否在所有目标场景保持一致。

## 2. 验证版本的基础

验证应基于当前原生 iOS 拍摄闭环：

```text
选择模板 → 授权相机与相册写入 → 参考蒙版取景
  → 拍摄 → 保存到系统相册 → 继续拍摄
```

模板只表达构图引导，不进入最终照片。相机能力由设备实际支持范围决定；蒙版与 UI 不承担镜头、照片捕获或保存职责。默认不申请整个相册的读取权限；Live Photo 麦克风权限按实际需求处理，不能阻断静态拍摄。

产品验证前先确认测试场景可稳定拍摄并保存，避免把会话、权限或输出错误归因为蒙版无效。相机稳定性与成片检查按照当前相机文档完成，不为此恢复历史 Expo 实现。

## 3. 模板发现与选择

首轮优先选择差异明确的线条、点、对称轴和上下关系模板；具体模板仍需结合当前内容确认。每个测试模板准备：

- 一张可辨认构图效果的真实示例。
- 简短适用场景与使用条件。
- 需要调整几何时，保留原版本与候选版本的实验标识。

先让测试者描述眼前想拍的主体，再独立选择模板，记录是否选错、是否换模板以及选择耗时。正式分类与示例内容尚未全部落地，可以使用最小验证材料开展观察，不提前建设收藏、远程内容或 AI 推荐。

## 4. 有对照的实拍

每个优先模板选择两个可重复拍摄的场景，每组完成：

1. 无蒙版，由拍摄者自行构图。
2. 使用当前蒙版。
3. 使用候选几何；没有候选时重复当前蒙版。

尽量保持地点、拍摄对象、光线、设备与相机设置一致，调整顺序或记录顺序影响。记录从相机打开到拍摄完成的时间、是否隐藏指引、最有帮助或干扰的部分。评价成片时隐藏实验版本，收集偏好排序和具体原因。

单张成功不能证明参数已经有效；先保留对照结果，再决定主体目标区、倒影引导或模板展示范围的调整。

## 5. 预览与成片检查

产品效果验证同时保留以下技术检查，以便区分模板问题与相机映射问题：

- 蒙版、点击聚焦位置与成片中的目标区域是否一致。
- 横竖画幅、设备持握方向与前置镜像是否正确。
- 实际倍率、镜头选择和成片尺寸是否符合测试记录。
- 隐藏指引不会影响拍摄输出，保存结果不包含构图线。

基础静态验证完成后，再检查 Live Photo 等输出组合，避免混合不同功能的结果。

## 6. 实验记录与结论

每轮使用独立日期记录，不依赖临时 Git 分支名称定位实验。至少记录设备、系统、构建或可追溯代码版本（如有）、样本、模板与几何版本、步骤、失败和判断限制。原始图片若在仓库外，说明存放方式，不把本机绝对路径当成团队可用链接。

结果分别标记：

- 已完成观察与证据支持的结论。
- 未覆盖场景及待验证问题。
- 待优化的内容、几何或交互。

新的待办归入 [后续工作](./next-steps.md)，完成证据留在实验记录，不以计划中的目标指标当成验收结果。
