# Framewise 构图蒙版有效性验证

本文定义技术 POC 完成后的真实产品验证阶段。内容会随需求讨论继续补充，不代表相关能力已经实现。

## 1. 阶段定位

当前已经完成技术 POC，证明以下链路在 Expo SDK 57 中可以成立：

```text
真实相机预览 + Canvas 构图覆盖 + 缩放 + 拍摄
```

当前阶段不再验证技术能否实现，而是验证产品的核心假设：

> 用户在真实相机画面上看到构图蒙版后，能否更容易完成构图，并拍出更符合预期的照片。

这一阶段完成后，通过真实模板和真实拍摄结果判断产品是否值得继续迭代。

## 2. 产品原则

Framewise 不重新设计一套相机。产品的核心是在尽量保留设备原生相机能力和操作习惯的基础上，为真实相机预览增加构图模板蒙版。

```text
设备相机能力 + Framewise 构图蒙版
```

模板和 Canvas 负责构图表达；相机能力层负责预览、镜头、变焦、拍摄和保存。两者保持独立，使后续替换相机实现时不需要重做模板数据和蒙版渲染。

## 3. 验证版本拍摄流程

```text
选择模板
  → 检查相机权限和相册写入权限
  → 打开带构图蒙版的相机
  → 点击快门
  → 直接保存到系统相册
  → 显示轻量保存反馈并继续拍摄
```

- 目标流程不包含拍摄后的照片预览页。
- 相册只申请保存照片所需的写入权限，不申请读取整个相册。
- 权限被永久拒绝时，提供明确说明和打开系统设置的入口。

## 4. 原生倍率与镜头能力

真实倍率是关键需求。相机界面需要在设备支持时显示类似 `0.5x`、`1x`、`2x`、`5x`、`10x` 的真实倍率，并尽可能使用物理镜头或原生虚拟多镜头设备的切换点。

真实倍率不阻塞本阶段验证。验证版本继续使用 `expo-camera` 的归一化 zoom 和现有双指缩放，不显示未经设备数据支持的倍率标签。完成模板选择和自动保存流程后，使用真实模板拍摄照片，验证构图蒙版是否有帮助。

当前 `expo-camera` 的 `zoom` 只提供 `0...1` 的归一化控制，不能跨平台可靠获得真实倍率和镜头切换点：

- iOS 可以取得可用镜头名称，但 Expo API 不提供完整倍率信息。
- Android 的 Expo API 不提供对应的镜头列表和真实倍率范围。
- 不得把归一化 zoom 值伪装成真实倍率。

实现该能力时再根据真机验证选择方案：

1. 继续使用 `expo-camera`，接受有限的倍率能力。
2. 使用提供更完整相机设备信息的 React Native 相机库。
3. 使用 Expo Native Module 分别接入 iOS AVFoundation 和 Android Camera2/CameraX。

决策时重点比较：真实倍率数据、物理镜头切换、预览与成片一致性、Expo SDK 兼容性、维护成本和双平台行为差异。

## 5. 验证版本完成边界

- 首页选择一个内置构图模板。
- 进入相机前处理相机权限和相册写入权限。
- 在真实相机预览上显示对应的构图蒙版。
- 支持双指连续缩放，不显示虚假的倍率数值。
- 点击快门后直接保存到系统相册。
- 保存成功后提供轻量反馈，并允许继续拍摄。
- 不提供结果预览、照片历史、编辑、评分或 AI 能力。

验证版本完成后进入真实拍摄，根据照片结果判断模板表达、引导位置和交互是否需要调整。

## 6. 实拍验证重点

- 用户能否快速理解蒙版表达的构图意图。
- 蒙版是否能帮助用户调整主体位置、比例和留白。
- 相机预览、蒙版位置和最终照片是否一致。
- 用户是否因为蒙版更快完成构图，或对结果更满意。
- 哪些模板有效，哪些模板造成干扰或限制。
