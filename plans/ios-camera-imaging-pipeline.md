## 1. 已确认的问题

当模板方向与手机拍摄方向不一致时，例如竖持手机使用 `4:3` 横版模板：

- 屏幕会为了最大化利用空间，以 `3:4` 竖向区域显示相机预览，并旋转构图模板。
- 最终文件仍应遵循模板定义的 `4:3` 横向输出契约。
- 当前成片的方向、可见范围或内容朝向无法与快门前的取景画面保持一致。

这属于成像正确性问题，不是轻微的 UI 偏差。用户可以用任意持机方向拍摄任意模板，但最终
成片必须准确对应取景器承诺的内容。把最终 `4:3` 文件转回拍摄时的 `3:4` 展示方向后，四边
内容必须与快门前的取景器一致。

## 2. 当前链路为什么不足

当前实现存在两套彼此独立的几何逻辑：

1. `CameraView` 根据屏幕尺寸，在模板原始比例及其倒数之间选择面积更大的预览区域，并可能
   单独旋转 `CompositionCanvas`。
2. `CameraPreview` 使用 `AVCaptureVideoPreviewLayer.resizeAspectFill` 显示相机内容。
3. 拍摄时 `AVCaptureDevice.RotationCoordinator` 只提供设备与传感器的输出方向。
4. 旧版 `LivePhotoProcessor` 不知道预览层实际显示了传感器的哪个区域，只在方向归一化后的
   完整图片中央按模板比例裁切。

仅把模板的 `90°` 布局旋转加减到 capture connection 并不能解决问题。2026-09-19 的实验
证明，这会改变最终文件方向，但仍不能保证成片内容与预览一致，并可能让内容整体侧转。

## 3. 当前成像模型

成像链路分为三层，禁止在同一步骤中混用它们的坐标：

1. **原始采集事实**：`CameraFramingSnapshot` 冻结 capture rotation、前摄镜像、捕获坐标到屏幕
   预览坐标的旋转，以及 `AVCaptureVideoPreviewLayer` 将当前可见区域换算出的 metadata rect。
   它不包含模板或 UI 布局数据。
2. **预览承诺**：照片先且只先应用相机自身的 EXIF / track orientation，再把冻结的 metadata
   rect 映射到照片输出坐标。裁切必须以这个实际可见区域为边界，不能只根据预览宽高比从完整
   照片中央猜测 `resizeAspectFill` 的结果。
3. **输出契约**：`CameraOutputPlan` 在快门时从 `CameraView` 冻结已经完成布局的预览宽高比、
   模板最终比例，以及模板坐标到预览坐标的四分之一圈旋转。处理器对完整的预览裁切结果做
   整体旋转，不能再按模板比例二次裁切。

例如竖持手机拍摄 `4:3` 模板时，处理器先得到与取景器一致的 `3:4` 内容，再整体旋转为 `4:3`。
这一步只交换内容的坐标方向，不改变第一阶段保留下来的像素集合。

静态照片与 Live Photo paired movie 必须消费同一份 `CameraOutputPlan`。快门后不得再次读取
可变的设备方向、预览布局、模板或镜像状态。保存前还必须验证“预览裁切比例经过整体旋转后”
与模板目标比例一致，避免生成 `1:1` 等错误画幅。

## 4. 最低验收矩阵

每一种组合都需要对照明显位于四边和四角的参照物，确认预览与成片一致：

- `3:4` 模板：竖持、左横持、右横持。
- `4:3` 模板：竖持、左横持、右横持。
- 后摄与前摄，包含前摄镜像语义。
- 普通照片与 Live Photo 的静态图、配对视频。
- `0.5×`、`1×`、长焦及手势缩放。
- 模板方向与持机方向相同、相反两类路径。

验收不只检查输出宽高比和 EXIF 方向。必须确认预览边缘可见内容、主体位置、构图线位置与
最终照片逐一对应；允许由底层照片管线带来的极小视场差异，但不能出现明显二次裁切、偏移、
镜像错误或整幅侧转。

## 5. 当前实现检查点

- `CameraView` 负责预览布局和模板叠加；快门时只传递模板输出比例及模板到预览的旋转结果。
- `CameraPreview` 在布局、设备方向或镜像变化时生成最新的 `CameraFramingSnapshot`，其中包含
  预览层按当前 `videoGravity` 换算出的可见 metadata rect。
- `CameraModel.capturePhoto()` 在快门时冻结快照；捕获进行中不再读取可变的预览状态。
- `CameraCaptureService` 用快照配置照片输出的旋转与镜像，并通过照片输出自己的坐标转换 API
  将可见 metadata rect 换算成归一化照片区域。
- `LivePhotoProcessor` 对照片的 EXIF orientation 和视频的 preferred transform 各应用一次，
  然后执行同一份“真实预览区域裁切 → 整幅输出旋转”计划。

工程已通过 generic iOS Simulator 的完整构建。由于模拟器不能验证真实摄像头的传感器方向、
前摄镜像和 Live Photo 配对视频，本检查点仍需完成第 4 节真机矩阵后才能标记为已解决。
