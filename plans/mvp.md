# Framewise MVP

## 1. 验证目标

验证最短产品链路是否成立：用户选择一个内置构图模板，在真实相机画面上看到对应引导，完成拍照，并在结果页检查照片。

```text
选择模板 → 打开相机 → 按蒙层构图 → 拍照 → 检查结果 → 重拍或完成
```

MVP 只验证静态模板是否能帮助用户完成拍摄，不验证 AI、内容规模和商业模式。

## 2. MVP 范围

### 必须完成

1. 在应用代码中写死 2 个构图模板。
2. 首页展示模板名称、用途和构图缩略图。
3. 点击模板进入相机页，并读取正确的 `templateId`。
4. 正常申请和处理相机权限。
5. 使用 Expo Camera 展示后置相机预览。
6. 使用 React Native Skia 在预览上绘制对应的矩形、线条或定位点。
7. 点击快门拍摄一张照片。
8. 拍摄后进入结果页，完整展示本次照片。
9. 结果页支持“重拍”和“完成”。
10. 蒙层只用于辅助构图，不出现在最终照片中。

### 暂不实现

- 保存到系统相册
- 前后镜头切换
- 闪光灯、缩放和点击对焦
- 用户自定义或编辑模板
- 网络请求、远程模板和后台管理
- 登录、作品历史和本地数据库
- AI 识别、实时调整提示和自动评分
- 照片滤镜、裁切或修图
- 动画和 Reanimated

## 3. 写死模板

MVP 使用两个差异明显的模板，以验证模板选择和蒙层切换，而不是验证模板数量。

### 模板 A：居中全身照

- 人物位于画面中央。
- 人物框约占画面高度的 76%。
- 头顶保留少量空间。
- 提示文案：“让人物完整站进框内”。

### 模板 B：右侧留白半身照

- 人物位于画面左侧。
- 右侧保留环境空间。
- 使用一条三分线辅助对齐。
- 提示文案：“人物靠左，右侧留出环境”。

建议数据：

## 4. 页面流程

### `/` 模板列表

- 读取本地 `templates` 数组。
- 使用同一个 `SkiaCompositionOverlay` 渲染模板缩略图。
- 点击卡片进入 `/camera/[templateId]`。

### `/camera/[templateId]` 相机页

- 根据路由参数查询模板。
- 请求相机权限并处理加载、拒绝和允许状态。
- 展示固定竖屏 `3:4` 的 `CameraView`。
- 在相机预览上叠加透明 Skia Canvas。
- 相机 `onCameraReady` 前禁用快门。
- 拍照期间锁定快门，避免并发调用。
- `takePictureAsync` 成功后，将照片 URI 和尺寸放入拍摄会话并进入 `/review`。
- 离开页面时卸载相机预览。

### `/review` 结果页

- 从拍摄会话读取照片 URI。
- 按照片原始比例完整显示，不叠加构图模板。
- “重拍”清除当前照片并返回原模板相机页。
- “完成”清除拍摄会话并返回模板列表。
- URI 缺失或失效时返回模板列表，不显示空白页面。

## 5. 状态

MVP 不引入第三方状态库。

- 模板：只读本地数组。
- 相机权限、准备状态和拍照状态：相机页本地 state。
- 当前模板 ID、照片 URI、宽度和高度：`CaptureSessionProvider`。

```ts
type CaptureSession = {
  templateId: string;
  photoUri: string;
  width: number;
  height: number;
};
```

## 6. 异常状态

MVP 必须能够显示并恢复以下状态：

- 相机权限尚未决定
- 相机权限被拒绝
- 模板 ID 不存在
- 相机挂载失败
- 相机尚未准备完成
- 拍照失败
- 结果页没有有效照片

错误处理保留在对应页面，不增加全局错误系统。

## 7. 完成标准

以下条件全部满足，MVP 才算完成：

- 两个模板都能从首页正确打开。
- 两个模板在相机中展示不同且正确的 Skia 蒙层。
- 蒙层与相机预览保持相同的 `3:4` 构图区域。
- 用户可以连续完成“选择模板、拍照、检查结果”。
- 结果照片方向正确，没有拉伸或明显裁切异常。
- 最终照片中没有构图线条。
- “重拍”返回同一个模板，“完成”返回模板列表。
- 快速连续点击快门不会触发多次拍摄或崩溃。
- 拒绝相机权限时不会出现黑屏或无响应。
- 至少在一台 iPhone 和一台 Android 真机上走通完整流程。
- TypeScript、lint 和 Expo 配置检查通过。

## 8. 实现顺序

1. 安装并配置 `expo-camera` 与 `@shopify/react-native-skia`。
2. 建立模板类型、写死两个模板并实现模板查询。
3. 实现可复用的 `SkiaCompositionOverlay`。
4. 实现模板列表和缩略图。
5. 实现相机权限、预览、蒙层和快门。
6. 实现拍摄会话与结果页。
7. 真机检查预览和结果照片的比例、方向与裁切。
8. 修复阻断完整流程的问题后停止开发，进入用户验证。

## 9. MVP 之后

只有静态模板拍摄链路验证通过后，再依次考虑：

1. 保存到系统相册。
2. 扩充到 5 至 8 个真实模板。
3. 前后镜头、闪光灯等相机能力。
4. 本地 AI 实时识别和调整提示。
