# Framewise 首个用户版本计划

> 状态：规划中。当前技术 MVP 作为验证基础；首个用户版本将重做原生相机，并在此基础上完成模板、运营和发布能力。

## 1. 版本目标

首个用户版本面向摄影新手和掌握简单拍摄技巧的用户。产品需要让用户在一分钟内找到适合当前场景的构图方式，理解引导，并通过原生相机完成一次可靠拍摄。

```text
发现模板
  → 理解构图意图
  → 使用蒙版取景
  → 聚焦、测光和调整曝光
  → 拍摄并保存
  → 回看构图效果
  → 收藏或再次使用
```

首版默认边界：

- 同时面向 iOS 与 Android，先开发和验证 Android 原生相机，再完成 iOS。
- 首发语言为简体中文。
- 不登录也能完成全部核心流程。
- 模板与相机核心体验离线可用。
- 照片以系统相册为正式存储位置。
- iOS 支持系统 Live Photo；Android 首版保存普通照片。
- 不包含 AI 评分、社区、视频、复杂编辑和用户自定义模板。

## 2. 标记说明

- **[核心]**：产品价值或拍摄可靠性的组成部分，未完成时不能发布。
- **[基础]**：发布、维护、反馈或合规所需能力，未完成时不能正式运营。
- **[完善]**：首版体验需要，但可以在核心闭环稳定后集中实现。

实现状态：

- **复用**：当前代码已经提供可继续使用的基础。
- **重做**：当前已有验证实现，但首版需要替换或重新设计。
- **新增**：当前尚未实现。

## 4. 总体实施顺序

```text
阶段 0  相机架构与交互约定
  ↓
阶段 1  Android 原生相机
  ↓
阶段 2  Android 真机验收
  ↓
阶段 3  iOS 原生相机与 Live Photo
  ↓
阶段 4  双平台相机验收
  ↓
阶段 5  蒙版与模板迭代
  ↓
阶段 6  完整用户闭环
  ↓
阶段 7  可持续运营能力
  ↓
阶段 8  UI、发布与商店打磨
```

相机交互和预览布局边界在阶段 0 确定；颜色、字体、动效、间距等完整视觉调整留到阶段 8。

## 5. 阶段 0：相机架构与交互约定

### 5.1 跨平台能力接口

- **[核心][新增]** 定义 Framewise 自有的 `CameraCapabilities`、镜头、倍率和闪光灯类型。
- **[核心][新增]** 定义普通照片与 Live Photo 的 `CaptureResult`。
- **[核心][新增]** 定义相机准备、处理中、捕获中、保存中、成功、失败和中断状态。
- **[核心][新增]** 定义前后台、来电等系统中断后的恢复行为。
- **[核心][新增]** 定义聚焦、测光、曝光、镜头切换和捕获方法。
- **[基础][新增]** 定义稳定的原生错误分类，供界面反馈和错误监控使用。
- **[核心][新增]** 原生平台类型不得扩散到模板、路由和业务页面。

### 5.2 坐标与视口

- **[核心][新增]** 明确原生预览矩形、传感器画面、照片输出与模板画布的映射。
- **[核心][新增]** 蒙版、点击聚焦和最终成片必须共用同一裁切模型。
- **[核心][新增]** 处理横竖方向、设备旋转、前置镜像和安全区域。
- **[核心][新增]** 明确 `aspect fill` 产生的裁切位置，不能分别由原生层和 React Native 猜测。

### 5.3 相机交互

- **[核心][新增]** 单击预览设置聚焦点与测光点。
- **[核心][新增]** 点击后上下滑动调整曝光补偿。
- **[核心][新增]** 长按锁定或解除 AE/AF。
- **[核心][新增]** 双指连续缩放。
- **[核心][新增]** 点击真实倍率切换镜头或缩放点。
- **[核心][新增]** Skia 蒙版不拦截相机手势。
- **[完善][新增]** 聚焦框、曝光太阳、锁定状态和失败状态的交互原型。

### 5.4 阶段完成标准

- Android 与 iOS 能在同一 TypeScript 接口下表达各自能力。
- iOS Live Photo 已进入接口设计，不需要在实现 iOS 时破坏 Android API。
- 相机手势不存在单击、滑动、长按、捏合之间的未决冲突。
- 预览和坐标变换规则可以被自动测试。

## 6. 阶段 1：Android 原生相机

Android 使用 CameraX 建立完整纵向拍摄链路。

### 6.1 原生预览与生命周期

- **[核心][重做]** 实现可供 React Native 使用的原生相机 View。
- **[核心][重做]** 启动、停止和释放相机会话。
- **[核心][新增]** 处理页面切换、应用前后台和系统中断。
- **[核心][新增]** 报告准备状态、能力变化和原生错误。
- **[核心][新增]** 避免重复挂载、相机占用和黑屏。

### 6.2 镜头与取景

- **[核心][重做]** 查询前后相机和设备实际能力。
- **[核心][重做]** 使用真实 zoom ratio，不再使用 Expo 归一化 zoom。
- **[核心][新增]** 根据设备能力生成倍率入口。
- **[核心][新增]** 支持倍率点击和双指连续缩放，并保持状态一致。
- **[核心][新增]** 设备不支持的镜头或控制不显示、不伪装。

### 6.3 聚焦、测光和曝光

- **[核心][新增]** 默认连续自动对焦和自动曝光。
- **[核心][新增]** 点击任意预览位置进行 AF、AE 和 AWB 测光。
- **[核心][新增]** 根据设备实际范围设置曝光补偿。
- **[核心][新增]** 支持 AE/AF 锁定和恢复自动状态。
- **[核心][新增]** 镜头切换或相机重启时正确重置状态。

### 6.4 拍摄与保存

- **[核心][重做]** 捕获普通照片并保存到系统相册。
- **[核心][重做]** 正确处理方向、前置镜像、尺寸和质量。
- **[核心][新增]** 捕获和保存期间防止并发操作。
- **[核心][新增]** 明确区分捕获失败与保存失败。
- **[核心][新增]** 失败后允许恢复或重试，禁止显示假成功。
- **[核心][新增]** 管理临时文件并在适当时机清理。

### 6.5 蒙版集成

- **[核心][复用]** 原生预览、Skia 蒙版和 React Native 控件保持 sibling 分层。
- **[核心][重做]** 蒙版视口适配原生预览裁切。
- **[核心][重做]** 点击坐标与蒙版位置经过同一视口转换。
- **[核心][重做]** 验证最终照片构图区域与预览一致。

### 6.6 最小诊断能力

- **[基础][新增]** 在开发和内测阶段收集 JS 未捕获异常与 Android 原生崩溃。
- **[基础][新增]** 主动记录相机启动、镜头、聚焦、捕获和保存等关键非致命错误。
- **[基础][新增]** 附带应用版本、构建号、系统版本、设备和相机能力上下文。
- **[基础][新增]** 不记录照片、相机画面、照片 URI 或资源标识。
- **[基础][新增]** 具体组件在实施阶段根据兼容性、网络、隐私和成本选型。

## 7. 阶段 2：Android 真机验收

- **[核心]** 至少覆盖多个品牌、系统版本、屏幕比例以及单摄和多摄设备。
- **[核心]** 验证首次授权、拒绝、永久拒绝和设置恢复。
- **[核心]** 验证前后镜头、真实倍率、点击聚焦、测光、曝光补偿和 AE/AF 锁定。
- **[核心]** 验证横竖方向、前置镜像、预览裁切和最终照片一致性。
- **[核心]** 验证连续拍摄、快速操作、前后台切换和低存储空间。
- **[核心]** 不要求所有设备能力相同，但必须正确报告能力并自然降级。

通过条件：核心拍摄与保存可靠，设备差异不会造成黑屏、崩溃、假成功或错误的能力展示。

## 8. 阶段 3：iOS 原生相机与 Live Photo

iOS 使用 AVFoundation 和 PhotoKit，在阶段 0 的相同产品接口下实现。

### 8.1 基础相机能力

- **[核心][重做]** 原生预览、会话生命周期和系统中断恢复。
- **[核心][重做]** 前后相机、物理或虚拟多镜头和真实倍率。
- **[核心][新增]** 点击聚焦、测光、曝光补偿和 AE/AF 锁定。
- **[核心][重做]** 闪光灯、普通照片、方向、镜像和系统相册保存。
- **[核心][重做]** 原生预览与 Skia 蒙版坐标一致性。

### 8.2 Live Photo

- **[核心][新增]** 查询设备 Live Photo 支持能力。
- **[核心][新增]** 同时配置相机与音频输入。
- **[核心][新增]** 仅在用户需要 Live Photo 时申请麦克风权限。
- **[核心][新增]** 捕获静态照片和 paired video。
- **[核心][新增]** 使用 PhotoKit 创建系统识别的单个 Live Photo asset。
- **[核心][新增]** 捕获期间显示状态并限制冲突操作。
- **[核心][新增]** 记住用户 Live Photo 开关状态。
- **[核心][新增]** 不支持或麦克风权限不足时明确降级为普通照片。
- **[核心][新增]** 蒙版不得进入静态照片或 paired video。
- **[核心][新增]** 正确清理 paired video 临时文件。

### 8.3 阶段完成标准

- 系统“照片”可以将结果识别、播放、编辑和分享为 Live Photo。
- 普通照片和 Live Photo 均能可靠保存。
- 原生相机的对焦、曝光、镜头与方向行为满足同一产品交互。
- Live Photo 不可用时不会影响普通拍摄。

## 10. 阶段 5：蒙版与模板迭代

### 10.1 蒙版产品规范

- **[核心][重做]** 根据真实拍摄筛选有效蒙版，删除无效或干扰性模板。
- **[核心][重做]** 确定线条颜色、粗细、透明度和安全区规则。
- **[核心][重做]** 确定标注位置、显示时长、隐藏和重新显示行为。
- **[核心][新增]** 为横拍与竖拍分别设计模板，不通过简单旋转或拉伸生成。
- **[核心][新增]** 成片回看复用同一套几何映射。

### 10.2 首发内容包

- **[核心][重做]** 精选约 12–20 个差异明确、实拍有效的模板。
- **[核心][新增]** 按人像、风景、建筑街景、食物静物等用户场景组织。
- **[核心][新增]** 每个模板包含易懂名称、用途、拍摄指令和标签。
- **[核心][新增]** 为每个模板准备真实示例和蒙版叠加预览。
- **[核心][新增]** 增加模板数据完整性与几何合法性检查。

通过条件：用户无需理解专业构图术语，也能判断模板是否适合眼前场景并按引导完成拍摄。

## 14. 首版明确不包含

- 用户账号、登录和云同步。
- 社区、评论、关注和公开作品。
- AI 自动评分、实时识别和动态构图建议。
- 用户自定义或编辑模板。
- 视频拍摄。
- 手动 ISO、快门速度、白平衡、RAW、峰值对焦和直方图。
- 滤镜、复杂裁切和完整修图工具。
- 应用内独立照片资产库。
- Android 自定义动态照片或对厂商 Motion Photo 的兼容。
- 订阅、付费和复杂商业化。
- 远程模板内容管理后台。

## 15. 首版发布总验收

### 核心能力

- 用户能够找到、理解并选择适合当前场景的模板。
- Android 和 iOS 均使用 Framewise 原生相机实现完成拍摄。
- 蒙版、聚焦点、预览裁切和最终成片保持一致。
- 自动对焦和自动曝光可靠，用户可点击聚焦、调整曝光并锁定 AE/AF。
- 倍率和镜头来源于真实设备能力。
- iOS 能捕获并保存系统识别的 Live Photo。
- 普通照片和 Live Photo 不包含蒙版。
- 照片保存不存在无提示丢失或假成功。
- 用户可以回看成片与构图参考并继续拍摄。

### 运营与发布能力

- 可以识别当前产品版本、构建版本和更新版本。
- 可以安全发布、灰度、暂停和回滚兼容更新。
- 可以提示可选更新并在必要时强制升级旧原生包。
- 可以发现、定位和跟进原生崩溃、JS 异常与关键业务错误。
- 可以获得最小、匿名且不包含照片内容的产品使用反馈。
- 可以通过用户反馈入口获得主观问题和建议。

只有核心能力与运营发布能力同时满足，首个用户版本才进入商店正式发布。
