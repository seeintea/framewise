# 相机 UI 设计：克制取景器

> 状态：2026-10-05 确认的当前 UI 打磨基线，已实现独立 SwiftUI mock Preview，待接入正式相机、待真机验收。保留熟悉的拍摄布局与圆形快门，后续细化蒙版、模板切换、控件材质和操作手感。
>
> 本轮 UI 调整仅在 [CameraUIDesignPreview](../ios/Framewise/Features/Debug/CameraUIDesignPreview.swift) 中实现；正式 `CameraScreen` 与原有 `CameraDebugView` 保持现有行为。当前产品能力见[当前实现清单](current-status.md)，采集与输出契约继续遵循[新相机设计](ios-camera-architecture-v2.md)。构建通过不代表视觉、手势或真机验收完成。

## 当前预览与确认范围

- 当前设计与交互依据：[CameraUIDesignPreview.swift](../ios/Framewise/Features/Debug/CameraUIDesignPreview.swift)。默认单模板模式；Xcode Canvas 中的 `Camera UI design comparison` 展示单模板，`Camera UI design · Related masks` 展示多模板。Debug 设置中的“相机 UI 对比 · 新设计”进入默认单模板模式。
- 原实现对比入口：[CameraDebugView.swift](../ios/Framewise/Features/Debug/CameraDebugView.swift) 的 `Single mask` 与 `Related masks`。原有组件没有随本轮 Preview 改动。

用户已确认沿用这套布局与交互继续打磨，包括圆形快门、单倍率入口、底部曝光滑块、移到取景区下沿的构图说明入口，以及单 / 多模板共用拍摄控件行。接受目前的原生相机熟悉感，Framewise 的辨识度重点放在蒙版、构图注释与关联模板切换；若发布审核提出具体 UI 反馈，再针对反馈评估调整。

确认的是后续打磨基线，不表示所有图标尺寸、间距或动画细节永久冻结。当前 mock 不连接相机、权限或相册；两种模式的真实背景辨识度、手势和设备适配仍待验证。

## 已确认的方向

| 项目 | 设计决定 |
| --- | --- |
| 整体气质 | 延续“克制取景器”的深色、轻量、低装饰方向，画面优先；保留熟悉的原生拍摄操作，将 Framewise 的视觉识别放在构图辅助与模板体验上 |
| 预览位置 | 与当前原生代码一致，按可用区域居中、等比适配；不因工具栏或快门另行挤压、贴底或移动预览 |
| 画幅 | 完整显示选定画幅的边界，重点兼顾 9:16；在比例允许时用满屏宽，不为铺满更长的手机屏幕额外放大裁去画幅 |
| 按钮外观 | 返回、倍率、说明和镜头翻转等控件不加常驻深色底板，不增加独立底部操作面板；非零曝光值用紧凑胶囊表达已调整状态 |
| 快门 | 恢复原圆形快门：白色实心内芯与圆形外圈，沿用原 `CameraBottomControls` 的系统材质与版本回退 |
| 控件叠放 | 控件作为覆盖层，不参与预览尺寸计算；拍照控件可与预览重叠，切换画幅时保持屏幕位置稳定 |
| 单 / 多模板 | 相册、快门、镜头翻转共用同一行与水平位置；Related masks 只将整行抬高，下方增加关联模板选择条 |
| 页面文案 | 不显示 `Framewise` 页头、“当前构图”、模板名称（包括“居中主体”）等常驻标题 |

去掉模板名称是相机页面的展示决定，不等于删除“居中主体”模板数据，也不等于取消画幅选择、模板内容或现有构图注释能力。

## 预览布局契约

以 [CameraScreen](../ios/Framewise/Features/Camera/CameraScreen.swift) 和 [CameraViewportLayout](../ios/Framewise/Features/Camera/CameraViewportLayout.swift) 的现有规则为准。预览在包含顶部安全区、截至底部安全区上沿的区域内居中，导航工具与拍照控件采用覆盖层。

在全屏竖向页面中，设屏宽为 `W`、屏高为 `H`、底部安全区为 `B`，模板的竖向比例为 `r = min(模板宽, 模板高) / max(模板宽, 模板高)`：

```text
可用高度 = H − B
预览宽度 = min(W, 可用高度 × r)
预览高度 = 预览宽度 ÷ r
预览左边缘 = (W − 预览宽度) ÷ 2
预览上边缘 = (可用高度 − 预览高度) ÷ 2
预览中心 = (W ÷ 2, 可用高度 ÷ 2)
```

3:4、1:1、9:16 切换时只改变画幅尺寸，中心不变。实际实现使用运行时 geometry 与安全区，不硬编码某一机型的状态栏或导航栏高度。横向模板仍沿用现有竖屏展示与蒙版旋转规则。

以 390 × 844、底部安全区 34 的示意屏幕为例，单位为布局点：

| 画幅 | 预览尺寸 | 距屏幕顶部 | 中心 Y |
| --- | --- | --- | --- |
| 3:4 | 390 × 520 | 145 | 405 |
| 1:1 | 390 × 390 | 210 | 405 |
| 9:16 | 390 × 693.33 | 58.33 | 405 |

“完整画幅”指 UI 不额外截断选定比例的预览区域；传感器画面适配目标比例所需的裁切与当前成片处理契约继续保留。不能将这一设计要求解释为取消所有相机裁切。

## 控件与视觉层级

### 顶部与画幅

- 左侧为返回，右侧为闪光和 Live Photo；构图说明入口已移到取景区下沿。单模板 Preview 中间显示当前画幅，保持居中。
- 画幅轻按切换到下一个可用尺寸，最后一个回到第一个；长按约 0.5 秒，在比例按钮附近展开小浮层，勾选当前项，选择后收起。画幅选择使用贴近顶部按钮的浮层。
- 单模板 mock 循环为 `3:4 → 1:1 → 9:16 → 3:4`。正式选项仍应来自当前模板的可用变体与相机支持能力；单尺寸不能切换，不把三项示意比例加入真实模板。
- 当前 Related masks mock 沿用原 `CameraDebugView` 的测试范围，顶部不展示画幅入口，下方切换五个比例命名的 mock 模板。正式多模板页面中的画幅能力仍需依据真实模板变体接入；mock 的入口隐藏不能直接代替正式行为。
- 返回按钮维持当前箭头样式；本轮没有新增导航行为。闪光保留 off / auto / on 的语义，Live Photo 保留现有可用性与权限边界。

### 取景区下沿：倍率、曝光、构图说明

控件顺序为倍率、曝光、构图说明。继续按 `zoomLift` 思路避让快门，并按整组控件的实际高度计算；曝光位预留宽度，使非零数值出现或归零时旁边的按钮位置稳定。空间不足时两行显示，适配大字号。

| 控件 | 当前确认的展示与交互 |
| --- | --- |
| 倍率 | 只显示当前倍率与细小下划线；轻按切到下一个预设，最后一档回最小档。长按约 0.5 秒打开底部调整面板，内容只保留一个滑块；从微调值轻按时进入下一个更大的预设 |
| 曝光 | 太阳图标；零值只显示图标，非零值显示图标与带正负号的小数，如 `+0.7`、`−0.7`，一起放入紧凑胶囊。视觉文本省略 `EV`，辅助功能值保留单位 |
| 曝光面板 | 点击太阳打开底部面板，只保留一个滑块；无需标题、数字说明、两端图标、重置或关闭按钮，沿用系统拖拽收起。调整后保留本地值 |
| 构图说明 | 使用文档样式图标 `doc.text`，点击切换构图文字注释的显示，不改变蒙版线条显隐。可用颜色区分开关状态 |

倍率与画幅的轻按、长按采用互斥手势，长按松手不应额外触发一次切换。VoiceOver 提供直接打开倍率调整或画幅选择的命名操作；交互效果仍需运行验证。

### 底部与 Related masks

- 拍摄行固定为左侧小尺寸相册、中间圆形快门、右侧无底板的翻转镜头图标；单 / 多模板共用同一组件、相同水平排列。
- Related masks 将整行抬高，下方放关联模板选择条，选中项居中、暖色文字加细小标记，支持点击及左右滑动。切换关联模板和切换同一模板的画幅是两个独立操作。
- 当前 Preview 中拍摄行高 74pt，圆形快门外框 72pt、内芯 60pt；关联模板条高 44pt、与拍摄行间隔 16pt，单模板底部 padding 为 16pt、多模板为 0，因此同一屏幕与安全区条件下多模板拍摄行上移约 44pt。这些是 mock 布局依据，正式实现仍使用运行时 geometry 与安全区。
- 拍照操作保持固定屏幕位置，不跟随画幅上下跳动；不用一块常驻深色面板切断取景画面。
- 画幅较短时，控件可以落在预览外的页面底色上；画幅较长时，可以覆盖在预览上。不能为了让所有控件始终位于画面内而移动或裁切预览。
- 下沿倍率、曝光、说明整组接近快门时上移，保留间隔；关联模板条增加高度也不能挤压或移动取景区中心。
- 相册缩略图本身的细边与快门轮廓属于识别元素，不是此次去除的按钮背景容器。

### 色彩、对比与材质

以炭黑 / 近黑承托画面，文字和图标采用暖白，少量香槟色用于构图辅助或选中状态。当前 Preview 的暖白参考色为 `#F2F0E4`、强调色为 `#D4BC89`，圆形快门内芯为纯白。颜色与透明度仍需结合真实相机内容校准，不作为未经验证的全局设计 token。

第一轮细化统一工具图标粗细，以明暗表达关闭状态；曝光胶囊可视高度约 32pt，触摸区域仍至少 44pt。工具按钮按下时轻微变暗与缩小，Reduce Motion 时保留明暗反馈并关闭缩放动画；圆形快门沿用原按钮样式。画幅浮层用轻微底色与勾选表达当前项。

画面边缘可使用轻微、连续的渐暗和细小阴影保证图标可读，避免重新给每个按钮增加明显底板。渐暗与构图引导只用于屏幕显示，不进入普通照片或 Live Photo 成品。保持细线、留白和节制的文字，不增加品牌标题或装饰卡片。

SwiftUI Preview 使用系统字体与 SF Symbols，镜头翻转复用现有共享图标。正式自定义图标、字体和品牌素材仍由 [design-system](../design-system/README.md) 统一管理，不直接把历史 HTML 稿中的 Lucide 图标当作新增资产规范。

## 原型与原生实现的边界

| Preview / 概念稿中的表现 | 正式原生实现要求 |
| --- | --- |
| 固定手机外框、CSS 像素、固定安全区示例 | 遵循真实设备 geometry、安全区、Dynamic Type 与至少 44pt 的有效点击区域；不把 CSS 尺寸逐项复制为 SwiftUI 点值 |
| 当前后摄 mock 的 0.5 / 1 / 2× 循环和 0.5～2× 滑块；前摄 mock 为 1 / 1.3 两档 | 倍率档位与范围来自实际设备能力，保留前摄宽 / 窄模式的离散语义与后摄连续缩放；不把 mock 数值当作所有设备的能力 |
| 曝光 mock 为 −2～+2、步长 0.1，通过灰色占位画面亮度示意 | 接入现有曝光 bias 与设备范围，并与对焦测光、曝光反馈、切镜及场景复位同步；灰色占位亮度不是成像管线验证 |
| 构图辅助按钮在示意稿里显隐整条构图线 | 当前产品开关控制构图文字注释；本次未确认改成关闭全部蒙版，实施时保留现有语义 |
| 单模板使用示意圆形蒙版与“主体”文字；Related masks 使用五个比例命名的 mock，不加载真实蒙版 | 接入真实模板、变体及本地化注释，模板切换回默认变体；mock 的比例标签不替代产品模板名称或内容 |
| 闪光和 Live 仅改变本地状态 | 保留实际 off / auto / on 能力、权限、Live 可用性与降级行为 |
| 快门仅有简单闪动，部分图标不执行动作 | 保留真实采集状态、readiness、触感、保存反馈、相册入口、镜头切换及禁用规则 |
| 单 / 多模板拍摄行共用，关联模板条只在 Related masks 显示 | 保留正式关联模板输入与有序切换能力，不将 mock 参数当作正式导航数据；不新增常驻模板标题 |

当前 Preview 不申请权限、不启动相机、不读取或保存照片，没有接入真实曝光、倍率或实时视频层。相册仍为占位图标，快门仅演示显示反馈；不表示正式采集或保存验收通过。该 UI 方案不要求重写相机会话、方向处理、保存或成品加工，也没有引入新依赖或新的最低系统版本要求。

## 后续实施与验收

先在 [CameraUIDesignPreview](../ios/Framewise/Features/Debug/CameraUIDesignPreview.swift) 中继续精细化确认，再接入正式 [CameraScreen](../ios/Framewise/Features/Camera/CameraScreen.swift)、[CameraTopBarControls](../ios/Framewise/Features/Camera/CameraTopBarControls.swift)、[CameraBottomControls](../ios/Framewise/Features/Camera/CameraBottomControls.swift) 和 [CameraZoomControls](../ios/Framewise/Features/Camera/CameraZoomControls.swift)。预览定位、采集与输出契约保留，待办入口见[待实现与待优化](next-steps.md)。

- 对照修改前后的 3:4、1:1、9:16 边界与中心位置，确认新样式没有缩小、拉伸或额外截断画幅。
- 核对控件屏幕位置、倍率避让、明亮 / 暗色 / 复杂背景下的辨识度，以及不同设备安全区。
- 核对单 / 多模板拍摄行的水平一致性、上移间隔、关联模板条居中与滑动边界；覆盖五种画幅，并将真实模板切换与同模板尺寸切换分别验证。
- 核对轻按 / 长按区分、长按松手不额外切换、顶部浮层位置与关闭、底部滑块交互和曝光归零后的胶囊收起；确认设备真实能力范围与对焦曝光状态同步。
- 核对 VoiceOver、Dynamic Type、Reduce Motion、可触达范围和采集中状态，保留当前功能反馈。
- 按工程要求完成构建，并记录具体机型和场景的真机验收；构建成功不能替代视觉与交互验收。

2026-10-05 的 SwiftUI mock 按工程要求已完成 iOS Simulator 通用目标构建。用户根据单模板截图确认继续沿用本轮基线；该截图不覆盖所有画幅、Related masks、长按手感、真实背景或系统版本，尚无新增真机验收记录。
