## 已确认的方向

| 项目 | 设计决定 |
| --- | --- |
| 整体气质 | 延续第一版“克制取景器”的深色、轻量、低装饰方向，画面优先；建立 Framewise 自己的视觉识别，避免过度接近 Apple 相机 |
| 预览位置 | 与当前原生代码一致，按可用区域居中、等比适配；不因工具栏或快门另行挤压、贴底或移动预览 |
| 画幅 | 完整显示选定画幅的边界，重点兼顾 9:16；在比例允许时用满屏宽，不为铺满更长的手机屏幕额外放大裁去画幅 |
| 按钮外观 | 去掉返回、工具组、倍率、镜头翻转等控件外的常驻深色底板，不增加一块独立底部操作面板 |
| 快门 | 使用第二版的圆角方形快门：浅色实心内芯、细外轮廓与间隙，保留清晰的主操作层级 |
| 控件叠放 | 控件作为覆盖层，不参与预览尺寸计算；拍照控件可与预览重叠，切换画幅时保持屏幕位置稳定 |
| 页面文案 | 不显示 `Framewise` 页头、“当前构图”、模板名称（包括“居中主体”）等常驻标题 |

去掉模板名称是相机页面的展示决定，不等于删除“居中主体”模板数据，也不等于取消画幅选择、模板内容或现有构图注释能力。

## 预览布局契约

以 [CameraScreen](../ios/Framewise/Features/Camera/CameraScreen.swift) 和 [CameraViewportLayout](../ios/Framewise/Features/Camera/CameraViewportLayout.swift) 的现有规则为准。预览在包含顶部安全区、截至底部安全区上沿的区域内居中，导航工具与拍照控件采用覆盖层。

在全屏竖向页面中，设屏宽为 `W`、屏高为 `H`、底部安全区为 `B`，模板的竖向比例为 `r = min(模板宽, 模板高) / max(模板宽, 模板高)`：

```text
可用高度 = H − B
预览宽度 = min(W, 可用高度 × r)
预览高度 = 预览宽度 ÷ r
预览左边缘 = (W − 预览宽度) ÷ 2
预览上边缘 = (可用高度 − 预览高度) ÷ 2
预览中心 = (W ÷ 2, 可用高度 ÷ 2)
```

3:4、1:1、9:16 切换时只改变画幅尺寸，中心不变。实际实现使用运行时 geometry 与安全区，不硬编码某一机型的状态栏或导航栏高度。横向模板仍沿用现有竖屏展示与蒙版旋转规则。

以 390 × 844、底部安全区 34 的示意屏幕为例，单位为布局点：

| 画幅 | 预览尺寸 | 距屏幕顶部 | 中心 Y |
| --- | --- | --- | --- |
| 3:4 | 390 × 520 | 145 | 405 |
| 1:1 | 390 × 390 | 210 | 405 |
| 9:16 | 390 × 693.33 | 58.33 | 405 |

“完整画幅”指 UI 不额外截断选定比例的预览区域；传感器画面适配目标比例所需的裁切与当前成片处理契约继续保留。不能将这一设计要求解释为取消所有相机裁切。

## 控件与视觉层级

### 顶部

- 左侧为返回与构图辅助入口，中间为当前画幅，右侧为闪光和 Live Photo。
- 使用轻量线性图标与简短比例文本，去掉常驻胶囊或圆角矩形底板。选中态以克制的暖色或明暗差异表达，不借助大块填色。
- 画幅菜单展开时仍需要可读的菜单表面；“无按钮底板”不要求菜单也透明。
- 菜单内容仍来自当前模板的可用变体与设备能力，不把预览稿中的三项比例当成每个模板都必须具备的选项。

### 底部

- 中间为圆角方形快门，左侧为小尺寸相册缩略图，右侧为无底板的翻转镜头图标。
- 拍照操作保持固定屏幕位置，不跟随画幅上下跳动；不用一块常驻深色面板切断取景画面。
- 画幅较短时，控件可以落在预览外的页面底色上；画幅较长时，可以覆盖在预览上。不能为了让所有控件始终位于画面内而移动或裁切预览。
- 倍率位于预览下沿附近，选中项采用清晰文本与细小标记。接近快门时按现有 `zoomLift` 思路上移，保留间隔，不能重叠。
- 相册缩略图本身的细边与快门轮廓属于识别元素，不是此次去除的按钮背景容器。

### 色彩、对比与材质

以炭黑 / 近黑承托画面，控件采用暖白，少量香槟色用于构图辅助或选中状态。原稿参考色包括浅色快门 `#F2F0E4`、强调色 `#D4BC89`；颜色与透明度仍需结合真实相机内容校准，不作为未经验证的全局设计 token。

画面边缘可使用轻微、连续的渐暗和细小阴影保证图标可读，避免重新给每个按钮增加明显底板。渐暗与构图引导只用于屏幕显示，不进入普通照片或 Live Photo 成品。保持细线、留白和节制的文字，不增加品牌标题或装饰卡片。

概念稿使用系统无衬线字体与示意图标。正式自定义图标、字体和品牌素材仍由 [design-system](../design-system/README.md) 统一管理，不直接把预览用的 Lucide 图标当作新增资产规范。

## 原型与原生实现的边界

| 原型中的表现 | 原生实现要求 |
| --- | --- |
| 固定手机外框、CSS 像素、固定安全区示例 | 遵循真实设备 geometry、安全区、Dynamic Type 与至少 44pt 的有效点击区域；不把 CSS 尺寸逐项复制为 SwiftUI 点值 |
| 固定 0.5 / 1× / 2 与 CSS 缩放 | 档位、前摄宽窄模式和连续缩放沿用设备能力与现有相机实现 |
| 构图辅助按钮在示意稿里显隐整条构图线 | 当前产品开关控制构图文字注释；本次未确认改成关闭全部蒙版，实施时保留现有语义 |
| 闪光仅做开关、Live 仅改变状态 | 保留实际 off / auto / on 能力、权限、Live 可用性与降级行为 |
| 快门仅有简单闪动，部分图标不执行动作 | 保留真实采集状态、readiness、触感、保存反馈、相册入口、镜头切换及禁用规则 |
| 单模板拍摄画面 | 多模板切换组件的样式未在本次定稿；不得据此删除现有能力或自行恢复模板标题 |

本次归档不要求重写相机会话、采集、对焦曝光、方向处理、保存或成品加工，也没有引入新依赖、系统版本要求或新的产品功能。
